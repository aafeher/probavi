# Probavi internationalization (i18n)

This document is normative for how Probavi localizes user-facing CLI
output: the catalog format, the locale selection rules, the translation
boundary, and the gates that keep catalogs honest. English is the
canonical source language of the project and the fallback for
everything, always (AGENTS.md §5.7).

Status: foundation + Hungarian implemented 2026-08-02; language roadmap
in ROADMAP.md Phase 4.

---

## 1. The translation boundary

**Translatable** — prose written for a human reading the terminal:

- the `probavi` usage/help text,
- CLI diagnostics on stderr ("--config is required", "unknown command",
  …).

**Never translated** — machine contracts and operational surfaces, in
any language, ever:

- evidence records and everything inside them (schema §8 vocabulary,
  error codes, check names, details),
- the one-line JSON summaries of `probavi run` / `probavi gameday` and
  the JSON outputs of `evidence verify`, `evidence keygen`,
  `adapter probe`, `adapter conformance` (field names *and* values,
  including `skip_reason` strings pinned by docs/gameday.md),
- the adapter protocol, notification payloads, and config file keys,
- structured logs (slog): logs are grepped, shipped, and alerted on —
  translating them would break every runbook,
- conformance verdict tokens (`ok` / `FAIL`) on stderr: they mirror the
  JSON report vocabulary.

Not yet covered (tracked in ROADMAP): config-validation diagnostics from
`internal/config` (they require threading the translator into the
package), flag descriptions, and the Go flag package's own parse errors.
Wrapper lines of the form `probavi run: %v` stay as they are — the `%v`
carries an English error chain until the validation step lands.

## 2. Locale selection

The locale is resolved **once, in `main()`**, from the environment —
POSIX order with a Probavi-specific override, no CLI flag, no config
key:

```
PROBAVI_LANG  →  LC_ALL  →  LC_MESSAGES  →  LANG
```

The first non-empty value wins. Values are normalized like locale
strings: case-insensitive, codeset and modifier stripped
(`hu_HU.UTF-8` → `hu`), `C` and `POSIX` mean English. An unknown or
malformed value falls back to English silently — a wrong `LANG` must
never break a cron drill. Tests construct the translator explicitly, so
suites are deterministic regardless of the machine's environment.

## 3. Catalog format

One embedded JSON file per language under `internal/i18n/locales/`,
named `<tag>.json` (lowercase ISO 639-1):

```json
{
  "probavi run: --config is required": "probavi run: a --config megadása kötelező"
}
```

- **The key is the English text itself** (gettext convention), verbatim
  including format verbs and trailing newlines. A missing key means the
  English original is printed — fallback is structural, not a special
  case.
- Format verbs (`%s`, `%q`, `%d`, `%v`, …) must appear in the
  translation in the same order with the same verbs; translations may
  not add, drop, or reorder them.
- Catalogs are compiled into the binary via `go:embed`: a single static
  binary stays a single static binary, and a catalog cannot be swapped
  or corrupted at run time.

## 4. Gates (CI-enforced)

The message set is defined explicitly in `cmd/probavi/messages.go` — one
list containing every translatable string. Per locale, tests enforce:

1. **Completeness** — every message has a translation (a new user-facing
   string cannot ship untranslated for an already-supported language),
2. **No stale keys** — every catalog key is in the message list
   (translations cannot outlive their source text),
3. **Format-verb parity** — as defined in §3,
4. every embedded catalog parses.

A language is "supported" when its catalog exists and passes these
gates; partially translated languages do not ship. The gates are the
i18n analog of the schema golden tests: they keep human-language output
as honest as the machine contracts.

## 5. Adding a language

1. Copy an existing catalog under `internal/i18n/locales/<tag>.json` and
   translate every value (native-speaker review required before merge).
2. Run the test suite — the §4 gates must pass.
3. Tick the language in ROADMAP.md Phase 4.

No Go code changes are needed: the embedded directory is the registry.

## 6. Language policy

English is the default and the canonical source; translations are
derived artifacts. The supported-language roadmap (ROADMAP.md Phase 4,
decided 2026-08-02) is Hungarian first, then the official languages of
the EU in native-speaker order. Contributions for further languages are
welcome under the same gates.
